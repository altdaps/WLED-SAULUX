# SAULUX — руководство по установке, настройке и управлению

Руководство для форка [altdaps/WLED-SAULUX](https://github.com/altdaps/WLED-SAULUX).
Описанное поведение соответствует **16.0.1-saulux.8**, включая независимые переходы нескольких сегментов.

Прошивка основана на официальной **WLED 16.0.1**, использует **ESP-IDF 4.4 / Arduino 2**
и предназначена для **ESP32-WROOM-32 без PSRAM**, с физической flash-памятью **4 или 8 МБ**.
Название устройства и оформление — **SAULUX**; JSON API и интеграция WLED остаются совместимыми.

- [Скачать прошивки](https://github.com/altdaps/WLED-SAULUX/releases).
- [Англоязычная документация проекта](SAULUX.md).
- [Исходный код независимых переходов](wled00/saulux_line.cpp).

<a name="quick-start"></a>
## 1. Быстрый старт

1. Определите модель платы: **2I2O**, **5I4O** или **ETHERNET**.
2. Скачайте файл именно для этой модели из [Releases](https://github.com/altdaps/WLED-SAULUX/releases).
   Для пустого модуля нужен `_factory.bin`; для обычного OTA-обновления — `.bin` без `_factory`.
3. После установки подключитесь к точке доступа `saulux-xxxxxx`.
   Начальный пароль — **`wled1234`**; адрес интерфейса в режиме точки доступа — **`http://4.3.2.1/`**.
4. Настройте домашнюю Wi-Fi-сеть. На модели ETHERNET можно подключить сетевой кабель.
   Узнайте выданный адрес в роутере или используйте mDNS-имя платы.
5. В **Config → LED Preferences** задайте фактическое число светодиодов на каждом выходе.
   Начальная настройка — **30 SK6812 RGBW на выход**, порядок каналов **GRBW**.
6. Для отдельных линий создайте сегменты с нужными диапазонами светодиодов.
7. Сохраните команды `sauluxLine` как пользовательские API-пресеты и назначьте их кнопкам.
8. Скачайте резервные копии конфигурации и пресетов после настройки.

Модель задаётся установленной прошивкой. **Меню переключения модели нет.**

Параметры Ethernet:

| Сигнал / параметр | Значение |
| --- | --- |

Используется профиль WLED `ESP32-ETHERNET-KIT-VE` с `ETH_PHY_IP101` и `ETH_CLOCK_GPIO0_IN`.
Адрес PHY можно изменить в пределах **0–31** в разделе SAULUX настроек светодиодов.

### Логика входов и реле

Начальный тип входов — **кнопка без фиксации**, активный уровень **LOW**, внутренние подтяжки включены.
Прошивка трактует замыкание входа на землю как нажатие при прямом подключении кнопки к GPIO.
Подключение к разъёмам готовой платы должно соответствовать её аппаратной схеме.

Реле по умолчанию включается уровнем **HIGH**. Его инверсия настраивается в аппаратных настройках.
Прошивка назначает GPIO управления; возможности силовой части определяются самой платой.

Распиновка в исходниках: [saulux.cpp](wled00/saulux.cpp),
параметры Ethernet: [network.cpp](wled00/network.cpp).

<a name="firmware-files"></a>
## 3. Выбор файла прошивки и объёма flash

Пример имён файлов для версии `16.0.1-saulux.8`:

| Модель | Для OTA | Для первой установки через USB / UART |
| --- | --- | --- |
| 2I2O | `WLED_16.0.1-saulux.8_SAULUX_2I2O.bin` | `WLED_16.0.1-saulux.8_SAULUX_2I2O_factory.bin` |
| 5I4O | `WLED_16.0.1-saulux.8_SAULUX_5I4O.bin` | `WLED_16.0.1-saulux.8_SAULUX_5I4O_factory.bin` |
| ETHERNET | `WLED_16.0.1-saulux.8_SAULUX_ETHERNET.bin` | `WLED_16.0.1-saulux.8_SAULUX_ETHERNET_factory.bin` |

В релизе находятся **три варианта прошивки**, каждый в обычном и factory-исполнении,
а также `SHA256SUMS` и `manifest.json`.

**Обычный `.bin`** содержит приложение и применяется для OTA.
**`_factory.bin`** содержит также загрузчик и таблицу разделов; его записывают через USB / UART
с адреса **`0x0`**. Не загружайте factory-образ через веб-OTA.

### 4 и 8 МБ

Для одной модели используется одинаковый файл на модулях с 4 и 8 МБ flash.
Отдельного выбора объёма памяти в меню нет.

Разметка занимает первые 4 МиБ:

| Раздел | Размер |
| --- | --- |
| Приложение OTA 0 | 1,5 МиБ |
| Приложение OTA 1 | 1,5 МиБ |
| Файловая система | 960 КиБ |

На модуле с 8 МБ оставшиеся 4 МиБ этой разметкой не используются.
Физический размер flash в информации об устройстве не означает, что всё пространство доступно пресетам.
Обычное OTA не заменяет таблицу разделов.

Источник разметки: [WLED_ESP32_4MB_1MB_FS.csv](tools/WLED_ESP32_4MB_1MB_FS.csv).

<a name="first-install"></a>
## 4. Первая установка и переход с ранних версий

### Пустой модуль

1. Скачайте `_factory.bin` для своей модели.
2. Подключите модуль через подходящий USB / UART-интерфейс.
3. Запишите весь factory-файл с адреса `0x0`.
4. Перезапустите плату и выполните первоначальную настройку.

Пример для SAULUX ETHERNET и современного `esptool`:

```sh
python3 -m esptool --chip esp32 --port /dev/cu.usbserial-EXAMPLE write-flash 0x0 WLED_16.0.1-saulux.8_SAULUX_ETHERNET_factory.bin
```

Замените порт и имя файла. В Linux порт может иметь вид `/dev/ttyUSB0`, в Windows — `COM4`.
В старых версиях esptool команда может называться `write_flash`; синтаксис своей версии можно проверить
через `python3 -m esptool --help`.
[Документация esptool](https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/basic-commands.html).

### Уже установлена SAULUX 16.x

Для обновления той же модели используйте обычный `.bin` или **Auto update**.
При обычном обновлении сохраняются настройки сети, конфигурация и пресеты.

### Установлена ранняя SAULUX 17 / ESP-IDF 5

Первый переход на эту ветку 16.x выполняется **через USB / UART с factory-образом**.
Сначала сохраните конфигурацию и пресеты. Замена только приложения через OTA не заменяет загрузчик;
Espressif не поддерживает запуск приложения старого ESP-IDF на более новом загрузчике.
После перехода проверьте совместимость восстановленных настроек и диапазоны светодиодов.

Идентификатор совместимости этой ветки — **`SAULUX_16`**, прежней экспериментальной ветки — `SAULUX`.
Проверку прошивки отключать для обхода этого ограничения не нужно.
[Совместимость загрузчиков ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32/api-guides/bootloader.html#bootloader-compatibility).

### Смена аппаратной модели

Чтобы сменить модель, устанавливают соответствующую прошивку, а не редактируют имя модели в конфигурации.
При обнаружении другого ранее применённого профиля аппаратные параметры получают значения новой модели:
выходы, входы, реле, I2C/SPI и начальные длины лент.
Сеть и сохранённые пресеты сохраняются, но диапазоны сегментов внутри старых пресетов могут потребовать исправления.

<a name="network"></a>
## 5. Подключение к сети и имена устройств

Имя точки доступа и mDNS формируются из последних шести шестнадцатеричных символов
STA / базового MAC-адреса платы, без двоеточий, в нижнем регистре.

Для MAC `AA:BB:CC:12:34:56`:

| Параметр | Пример |
| --- | --- |
| Точка доступа | `saulux-123456` |
| Начальный пароль AP | `wled1234` |
| Адрес в режиме AP | `http://4.3.2.1/` |
| mDNS | `http://saulux-123456.local/` |
| Начальное отображаемое имя | `SAULUX` |

Если пароль AP уже изменён, используйте сохранённый пароль.
Имена AP и mDNS привязаны к самой плате и пересчитываются при загрузке,
в том числе после восстановления чужой конфигурации. Настройка другого имени в Wi-Fi-форме их не переопределяет.
Отображаемое имя, которое пользователь явно изменил, сохраняется.

Если `.local` не разрешается в вашей сети, откройте IP из списка клиентов роутера.
Для постоянного адреса удобно использовать резервирование DHCP по MAC-адресу нужного интерфейса.
Wi-Fi и Ethernet одной платы могут иметь разные IP; поле `ip` в информации об устройстве
может относиться к другому активному интерфейсу, чем адрес, по которому открыт браузер.

### Время: Москва и Саратов

В версии **16.0.1-saulux.8** в **Config → Time & Macros → Time zone** добавлены:

| Пункт меню | Смещение от UTC | Номер в конфигурации |
| --- | --- | ---: |
| `Moscow (UTC+3)` — Москва | +3 часа круглый год | 25 |
| `Saratov (UTC+4)` — Саратов | +4 часа круглый год | 26 |

Включите **Get time from NTP server**, выберите город и нажмите **Save**.
Летнее и зимнее время для этих пунктов не переключается.
Поле **UTC offset** задаёт дополнительную поправку в секундах поверх выбранного пояса.
Если раньше вы вручную выставляли в нём `10800` или `14400`, при выборе города
замените эту поправку на **`0`**, иначе смещение сложится дважды.
Обновление прошивки сохраняет выбранный пояс и ручную поправку; город автоматически не выбирается.

Источник правил: [база часовых поясов IANA](https://data.iana.org/time-zones/tzdb/europe).

<a name="led-settings"></a>
## 6. Настройка светодиодов, реле и индикации

Откройте **Config → LED Preferences**:

1. Проверьте модель в разделе **SAULUX device**. Она отображается для информации.
2. Для каждого используемого выхода задайте реальное количество светодиодов.
3. Проверьте тип **SK6812 RGBW** и порядок каналов под свою ленту; начальный порядок — **GRBW**.
4. Задайте ограничение тока под свой источник питания и подключённые ленты.
5. Проверьте входы, реле и необходимые аппаратные параметры.
6. Нажмите **Save**.

Начальные количества:

| Модель | Выходов | Светодиодов на выход | Всего |
| --- | ---: | ---: | ---: |
| 2I2O | 2 | 30 | 60 |
| 5I4O | 4 | 30 | 120 |
| ETHERNET | 1 | 30 | 30 |

Это исходные настройки, а не автоматически определённая длина подключённой ленты.
Обычное обновление того же профиля не должно возвращать настроенные длины к 30.

При первом обновлении со старых SAULUX-настроек WS2812 выполняется однократная миграция
на SK6812 RGBW с сохранением существующих GPIO, длин, порядка каналов и лимитов тока.
Последующие явные изменения типа ленты сохраняются.

### Параметры SAULUX и кнопки сохранения

- Адрес PHY: по умолчанию `1`, допустимы `0–31`.
- Индикатор статуса: обычная полярность active HIGH или инверсия active LOW.
- **Apply settings** применяет поля PHY / индикатора и перезапускает устройство при их изменении.
- **Save** сохраняет остальные параметры страницы LED Preferences.

Не используйте **Apply settings** вместо **Save**, если меняли длину ленты или другие LED-параметры.

### Индикатор статуса

| Состояние | Индикация |
| --- | --- |
| Есть сетевое подключение | Мигание примерно 1 раз в секунду |
| Работает AP без сетевого подключения | Мигание примерно 1 раз за 2 секунды |
| Нет подключения и AP не активен | Индикатор выключен |

У 2I2O отдельного статусного выхода нет. Индикация не означает состояние реле или сегмента.

<a name="segments"></a>
## 7. Выходы и сегменты

**Выход** — аппаратная линия данных на GPIO.
**Сегмент** — логический диапазон светодиодов, которому можно назначить собственные цвет, эффект и яркость.
На одном выходе можно создать несколько сегментов. Сегмент также может охватывать несколько выходов,
если его диапазон проходит через их общую логическую нумерацию.

Сначала настройте длины выходов, затем границы сегментов: изменение длин может сместить логические диапазоны.

### Пример: 105 светодиодов на одном выходе

В разделе **Segments** создайте три непересекающихся диапазона:

| ID | Start | Stop | Индексы светодиодов | Количество |
| --- | ---: | ---: | --- | ---: |
| 0 | 0 | 35 | 0–34 | 35 |
| 1 | 35 | 70 | 35–69 | 35 |
| 2 | 70 | 105 | 70–104 | 35 |

**Start включается в диапазон, Stop не включается.** Количество равно `Stop - Start`.
Эти значения — пример; постоянную разметку выбирайте под реальные линии.

### Пример: два выхода с разными длинами

Если первый выход содержит 60 светодиодов и начинается с индекса 0,
а второй содержит 90 и начинается с индекса 60:

| Линия | Диапазон сегмента |
| --- | --- |
| Первая | `start:0`, `stop:60` |
| Вторая | `start:60`, `stop:150` |

GPIO выхода не является ID сегмента. Например, `seg:1` не означает GPIO1.
Фактические ID и диапазоны можно посмотреть в `http://<IP>/json/state`.
После удаления или перестроения сегментов проверяйте ID в API и связанных пресетах.

<a name="line-control"></a>
## 8. Световая линия с кнопками по краям

Команда `sauluxLine` управляет выбранным существующим **одномерным сегментом**.
Самостоятельно создавать сегменты эта команда не умеет.

Если первый светодиод находится слева, направление `start` соответствует левому краю,
а `end` — правому. Для отдельного сегмента отсчёт ведётся от первого светодиода его диапазона.
Маска гашения применяется по физическим позициям внутри сегмента, после учёта отражения и смещения.

### Поведение без выполняющегося прохода

| Исходное состояние | Кнопка `start` | Кнопка `end` |
| --- | --- | --- |
| Сегмент выключен | Белое заполнение от начала к концу | Белое заполнение от конца к началу |
| Сегмент включён | Темнота движется от конца к началу | Темнота движется от начала к концу |

Новая команда включения из полностью выключенного состояния выбирает **Solid white**:
для RGBW используется выделенный канал **W**, для RGB — белый из RGB.
Яркость сегмента при таком включении устанавливается в 255; общая яркость остаётся текущей.
Reverse / Mirror отключаются для новой белой сцены.

При выключении сохраняются **текущий эффект, палитра, цвета, яркость сегмента и его геометрия**.
На ещё видимой части эффект продолжает работать. Принудительной замены цветного эффекта белым перед гашением нет.

### Повторное нажатие во время прохода

Нажатие **любой кнопки этого сегмента** разворачивает текущую границу с её положения.
Горящая часть не переносится на другой конец. Скорость сохраняется, действия в очередь не ставятся.
Повторное нажатие снова разворачивает движение.

Пример: полный проход задан как 2 секунды. Если заполнено примерно 40% линии,
обратный ход до полного выключения занимает примерно 0,8 секунды.
Изменение `tt` в команде разворота не меняет скорость уже выполняющегося прохода;
новая длительность применяется к следующему новому проходу.

После полного включения или выключения сторона следующей нажатой кнопки снова определяет новый проход.

### Master и состояние сегмента

Каждый сегмент имеет собственный таймер и состояние. Выключение одного не гасит остальные.
**Master остаётся включённым даже при выключенных сегментах.**
Реле, если оно следует за общим питанием WLED, при этом также не выключается от одного лишь гашения сегментов.

Если Master был выключен, команда включения восстанавливает общую яркость и включает только выбранный сегмент.
Остальные сегменты остаются выключенными.

В API поле `seg[].on` сразу показывает целевое состояние: при гашении оно уже равно `false`,
хотя последние светодиоды ещё выполняют переход. Яркость горящей части не уменьшается общей волной:
двигается граница.

Обычная команда изменения сегмента из интерфейса или Home Assistant прерывает переход этого сегмента.
Изменение общего питания или общей яркости прерывает все переходы.
Выбор сегмента в интерфейсе и изменение его имени не прерывают проход.
Запуск `sauluxLine` отменяет глобальный ночной таймер Nightlight.

<a name="button-presets"></a>
## 9. Создание пресетов и назначение кнопок

### Один сегмент, две кнопки

Для примера используем сегмент `0` и свободные ID пресетов `11` и `12`.
Если эти ID заняты, выберите другие.

1. Откройте раздел **Presets** и создание нового пресета.
2. Снимите **Use current state**, чтобы открыть поле **API command**.
   При редактировании существующего пресета аналогичная настройка называется **Overwrite with state**.
3. Вставьте команду для нужной стороны.
4. Укажите имя, например «Линия 1 — начало», и свободный **Save to ID**.
5. Сохраните. Для команды переключения не включайте **Apply at boot**.
6. Повторите для противоположного края.

Пресет 11, начало сегмента 0:

```json
{"sauluxLine":"start","seg":0,"tt":20}
```

Пресет 12, конец сегмента 0:

```json
{"sauluxLine":"end","seg":0,"tt":20}
```

Затем откройте **Config → Time & Macros** и назначьте действия:

| Кнопка | Короткое нажатие | Долгое нажатие | Двойное нажатие |
| --- | ---: | ---: | ---: |
| У начала линии | 11 | 11 | 11 |
| У конца линии | 12 | 12 | 12 |

**Одинаковый ненулевой ID во всех трёх действиях** включает выполнение на первом фронте нажатия,
без ожидания распознавания двойного или долгого нажатия. Удержание не запускает повторные переключения:
для следующего действия кнопку нужно отпустить и нажать снова.

Если назначить разные действия, используется обычная логика короткого, долгого и двойного нажатия WLED,
с соответствующим ожиданием распознавания.

Для SAULUX ETHERNET вход 1 — GPIO32, вход 2 — GPIO33.
Если DIN / первый светодиод расположен у входа 1, назначьте ему `start`, а входу 2 — `end`.

### Длительность

| `tt` | Полный проход |
| ---: | --- |
| 0 | Мгновенно |
| 5 | 0,5 секунды |
| 10 | 1 секунда |
| 20 | 2 секунды |
| 30 | 3 секунды |

`tt` — целое число от **0 до 655**, единица равна 100 мс.
Если поле не задано, используется текущая общая настройка длительности перехода.

### В каком виде должен сохраняться пресет

Начиная с `.7`, пользовательская API-команда сохраняется без автоматического добавления
`on`, `bs`, цветов и прочих полей текущего перехода. Само сохранение такой команды её не выполняет.

Старые развёрнутые пресеты тоже принимаются: ID берётся из `seg`, а добавленные старой версией
поля сцены и общего питания не используются для выполнения `sauluxLine`.

Допустима и объектная запись сегмента:

```json
{"sauluxLine":"end","seg":{"id":1},"tt":20}
```

Если `seg` отсутствует, выбирается текущий основной сегмент:

```json
{"sauluxLine":"start","tt":20}
```

Для нескольких линий лучше указывать ID явно: смена основного сегмента тогда не меняет назначение кнопки.

### Выключенное состояние после загрузки

Для загрузки используйте отдельный обычный пресет выключенного состояния и отметьте у него **Apply at boot**.
Не выбирайте команду `sauluxLine` в качестве стартовой: это переключение, а не фиксированное состояние.
Простой фиксированный OFF для всего устройства через API выглядит так:

```json
{"on":false,"tt":0}
```

Для обычного стартового пресета можно настроить сцену в интерфейсе, выключить Master,
затем сохранить текущее состояние с включённым сохранением яркости / состояния питания.

<a name="multiple-lines"></a>
## 10. Независимое управление несколькими линиями

Пусть созданы сегменты `0` и `1`. Для второй линии создайте ещё два пресета.
Каждый JSON ниже — отдельная команда отдельного пресета.

Пресет 21, начало сегмента 1:

```json
{"sauluxLine":"start","seg":1,"tt":20}
```

Пресет 22, конец сегмента 1:

```json
{"sauluxLine":"end","seg":1,"tt":20}
```

Пример назначения четырёх кнопок на **SAULUX 5I4O**:

| Вход | GPIO | Линия и сторона | Короткое / долгое / двойное |
| --- | ---: | --- | --- |
| 1 | 27 | Сегмент 0, начало | 11 / 11 / 11 |
| 2 | 26 | Сегмент 0, конец | 12 / 12 / 12 |
| 3 | 25 | Сегмент 1, начало | 21 / 21 / 21 |
| 4 | 33 | Сегмент 1, конец | 22 / 22 / 22 |
| 5 | 32 | Дополнительное действие | По необходимости |

Можно одновременно заполнять первый сегмент, гасить второй и оставлять третий с другим эффектом.
Нажатие кнопки первого сегмента разворачивает только его переход.
Полные времена прохода разных линий могут отличаться.

Для схемы «две кнопки на каждую линию» две линии требуют четырёх входов.
На плате с двумя входами другие сегменты можно управлять через интерфейс, Home Assistant или API.

<a name="json-api"></a>
## 11. JSON API и примеры команд

Во всех примерах замените `192.168.1.50` реальным адресом своего устройства.
Ни одна из приведённых команд не требует MQTT.

### Чтение состояния

```sh
curl --fail --silent --show-error http://192.168.1.50/json/state
```

Информация о версии, модели, MAC, количестве светодиодов и оценке тока:

```sh
curl --fail --silent --show-error http://192.168.1.50/json/info
```

Полезные поля `/json/info`:

| Поле | Значение |
| --- | --- |
| `ver` | Версия установленной прошивки |
| `brand`, `product` | Название SAULUX |
| `release` | Семейство совместимости `SAULUX_16` |
| `otaRelease` | Вариант: `SAULUX_2I2O`, `SAULUX_5I4O` или `SAULUX_ETHERNET` |
| `repo` | Репозиторий форка |
| `otaBase` | Адрес файлов OTA |
| `mac` | Идентификатор MAC, используемый API |
| `leds.count` | Общее количество светодиодов |
| `leds.pwr` | Расчётное потребление в мА |
| `leds.maxpwr` | Лимит тока, когда оценка / ограничитель активны |

### Запуск или разворот выбранной линии

```sh
curl --fail --silent --show-error \
  -H 'Content-Type: application/json' \
  -d '{"sauluxLine":"end","seg":1,"tt":20}' \
  http://192.168.1.50/json/state
```

Одна команда адресует один существующий сегмент. Для другой линии отправьте отдельную команду
с другим `seg`. Массив сегментов в `sauluxLine` не поддерживается.

### Обычное выключение одного сегмента

```json
{"seg":[{"id":1,"on":false}],"tt":0}
```

Это стандартная команда WLED: выбранный сегмент выключится без прохода `sauluxLine`.
Остальные сегменты не изменяются; видимость включённых сегментов зависит также от Master.

### Общее выключение

```json
{"on":false,"tt":0}
```

Команда выключает Master и всё устройство, включая все выполняющиеся переходы.
В отличие от неё, `sauluxLine` при гашении отдельной линии не выключает Master.

### Ограничения команды `sauluxLine`

- Работает с существующими активными одномерными сегментами.
- ID — целое число; строка `"1"` вместо числа `1` не подходит.
- Поддерживаются числовой `seg` и объект `seg` с `id`; массив не поддерживается.
- `start` и `end` пишутся строчными буквами.
- `tt` должен быть целым числом `0–655`.
- Настройки других сегментов, создание сегментов и общие команды лучше отправлять отдельными обычными запросами.

<a name="home-assistant"></a>
## 12. Home Assistant

### Подключение и сегменты

Добавьте интеграцию **WLED** в **Настройки → Устройства и службы** и укажите адрес SAULUX,
если автоматическое обнаружение не предложило плату. Брендинг SAULUX не меняет название интеграции.

Каждый сегмент получает отдельную сущность света. У него можно менять состояние, яркость,
цвет и эффект; палитра выбирается отдельной сущностью. Master управляет общим питанием и яркостью.
Для независимых линий используйте их сущности, а не общее выключение Master.
[Документация интеграции WLED](https://www.home-assistant.io/integrations/wled/).

### Основной светильник недоступен, а сегмент работает

При одном сегменте отдельный Master может быть недоступен, если отключена **Keep Master Light**.
Откройте параметры записи WLED для своей платы и включите эту опцию.
Она сохраняет отдельный Master и при изменении числа сегментов.
Если недоступны все сущности, сначала проверяйте адрес, сеть и журнал интеграции.
[Описание Keep Master Light](https://www.home-assistant.io/integrations/wled/#options).

### Вызов прохода из автоматизации

Обычное `light.turn_off` не запускает `sauluxLine`.
Можно активировать сохранённый API-пресет через сущность выбора пресета WLED,
либо отправить команду через `rest_command`.

Пример для `configuration.yaml`:

```yaml
rest_command:
  saulux_line_toggle:
    url: "http://192.168.1.50/json/state"
    method: post
    content_type: "application/json"
    payload: >-
      {"sauluxLine":"{{ endpoint }}","seg":{{ segment | int }},"tt":{{ duration | int }}}
```

После добавления конфигурации примените её способом, указанным в документации вашей версии HA;
для первоначальной настройки подходит перезапуск Home Assistant.

Действие для начала сегмента 1:

```yaml
action: rest_command.saulux_line_toggle
data:
  endpoint: start
  segment: 1
  duration: 20
```

Другая сторона того же сегмента:

```yaml
action: rest_command.saulux_line_toggle
data:
  endpoint: end
  segment: 1
  duration: 20
```

Оба действия являются переключениями: они учитывают состояние и разворачивают текущий проход.
Они не эквивалентны фиксированным командам «всегда включить» / «всегда выключить».
[RESTful Command в HA](https://www.home-assistant.io/integrations/rest_command/).

<a name="mqtt"></a>
## 13. Состояние кнопок в MQTT

Откройте **Config → Sync Interfaces → MQTT**:

1. Включите MQTT и укажите брокер, порт и необходимые учётные данные.
2. Задайте уникальный **Device Topic**, например `saulux/hall`.
3. Включите **Publish on button press**.
4. Сохраните и перезапустите устройство.

Device Topic задаётся отдельно от имени AP и mDNS.
Для нескольких плат используйте разные Device Topic.

### Состояние нажатия

| Модель | Топики |
| --- | --- |
| 2I2O | `<Device Topic>/input/1/state`, `<Device Topic>/input/2/state` |
| 5I4O | От `<Device Topic>/input/1/state` до `<Device Topic>/input/5/state` |
| ETHERNET | `<Device Topic>/input/1/state`, `<Device Topic>/input/2/state` |

Пример: `saulux/hall/input/1/state`.

| Payload | Смысл |
| --- | --- |
| `1` | Кнопка нажата |
| `0` | Кнопка отпущена |

Нумерация входов начинается с **1**, соответствует первым настроенным кнопочным входам
и по умолчанию совпадает с порядком разъёмов платы. Это не номер GPIO.

Состояния фильтруются по устойчивому уровню **50 мс**, публикуются с **QoS 1** и **retain**.
При подключении к брокеру отправляется снимок состояний; после переподключения он обновляется.
Удержание не создаёт непрерывный поток одинаковых сообщений.

При отключении публикации кнопок, отключении входа или переводе его в неподдерживаемый тип,
например аналоговый, прошивка удаляет соответствующее retained-состояние при доступном брокере.
Локальные действия кнопки не зависят от подключения MQTT.

### События короткого, долгого и двойного нажатия

Существующие события WLED имеют другую нумерацию, с **0**:

| Топик | Примеры payload |
| --- | --- |
| `saulux/hall/button/0` | `short`, `long`, `double` |
| `saulux/hall/button/1` | `short`, `long`, `double` |

Эти события публикуются без retain, с QoS 0. Не путайте их с `/input/1/state`.
Если все три действия кнопки привязаны к одному пресету, используется немедленное короткое действие,
а не отдельное распознавание долгого и двойного нажатий.

### Доступность

Топик `<Device Topic>/status` содержит `online` / `offline`.
Retained-состояние кнопки — последнее известное значение, а не подтверждение, что устройство сейчас в сети.
При обработке нажатий учитывайте также доступность устройства.

Исходники: [saulux_mqtt.cpp](wled00/saulux_mqtt.cpp), [button.cpp](wled00/button.cpp).

<a name="ota"></a>
## 14. Резервные копии и обновление по воздуху

### Что сохранять

В **Config → Security & Updates → Backup & Restore** скачайте:

- **Backup configuration** — `cfg.json`;
- **Backup presets** — `presets.json`.

Резервная копия конфигурации через обычный интерфейс не является полным дампом flash
и не содержит всех секретов из `wsec.json`. Сетевые пароли храните отдельно.
Копии полезны перед первой установкой, сменой модели и изменением разметки сегментов.

Восстановление конфигурации другой платы не меняет уникальное имя AP / mDNS текущей платы.
Пресеты с конкретными ID и диапазонами сегментов требуют совместимой разметки.

### Auto update из этого форка

1. Откройте **Config → Security & Updates → Manual OTA Update → Auto update**.
2. Дождитесь получения информации о релизе.
3. Запустите обновление и оставьте вкладку открытой до окончания загрузки и перезапуска платы.

Браузер получает файл подходящей модели из
[GitHub Pages этого форка](https://altdaps.github.io/WLED-SAULUX/), проверяет ожидаемые данные
и передаёт прошивку устройству. Для загрузки файла интернет нужен браузеру;
исходящий доступ в интернет самого ESP32 для этого механизма не требуется.

Вариант выбирается по `otaRelease`, зашитому в прошивку.
Сохранённое поле модели в конфигурации не перенаправляет обновление на другой вариант.
Проверку прошивки оставляйте включённой.

### Ручное обновление

Для ручного OTA загрузите обычный `.bin` своей модели из Releases и выберите его на странице обновления.
Не выбирайте `_factory.bin`.

Веб-обновление SAULUX использует файлы этого форка, а не исходного WLED.
Описание здесь относится именно к встроенной странице SAULUX; для иных внешних клиентов
проверяйте, откуда они предлагают загружать прошивку.

### Почему релиз есть, а Auto update ещё показывает предыдущий

Публикация релиза и развёртывание GitHub Pages — отдельные шаги workflow.
Дождитесь успешного **Publish OTA files to GitHub Pages**.
До него канал OTA может содержать предыдущую успешно развёрнутую версию.

<a name="troubleshooting"></a>
## 15. Диагностика частых проблем

| Симптом | Что проверить |
| --- | --- |
| Нет ожидаемой AP | Имя `saulux-` с суффиксом MAC; устройство могло подключиться к сохранённой сети |
| Не открывается `.local` | IP в роутере и поддержку mDNS в используемой сети |
| Ethernet не поднимается | Модель ETHERNET, IP101GRI, PHY address 1, тактирование GPIO0 и соответствие аппаратной схеме |
| Светится только начало ленты | Реальную длину выхода в LED Preferences и границы сегмента |
| Перепутаны цвета | Тип SK6812 RGBW и фактический порядок каналов ленты |
| Кнопка не вызывает проход | Номер входа, GPIO, тип кнопки и назначенные ID пресетов |
| Нажатие выполняется с задержкой | Одинаковый ненулевой пресет во всех трёх типах нажатия |
| `sauluxLine` не меняет нужную линию | Существование сегмента, его фактический ID и числовой `seg` |
| Вместо текущего эффекта перед выключением появляется белый | Версию `.7` или новее и наличие `sauluxLine` в API-пресете |
| Другие линии выключаются вместе с одной | Используется ли сегментная команда вместо общего `on:false`; обновлена ли прошивка с `.6` |
| Master показывает ON, хотя все сегменты погашены | Это штатное состояние независимых сегментов в `.7` |
| Основной светильник HA недоступен, но сегмент доступен | Опцию **Keep Master Light** в параметрах интеграции WLED |
| Не публикуются входы MQTT | MQTT, Device Topic, **Publish on button press**, доступность брокера |
| После отключения платы видна нажатая кнопка в MQTT | Retain хранит последнее значение; учитывайте `/status` |
| Auto update видит старую версию | Успешность развёртывания Pages, а не только создание GitHub Release |
| Не проходит проверка firmware | Правильность файла, семейство `SAULUX_16` и способ перехода со старой IDF 5 |

### Эффекты тусклее белой заливки

Проверьте последовательно:

1. Общую яркость Master.
2. Яркость самого сегмента.
3. Яркость выбранных цветов: красный `[36,0,0,0]` слабее `[255,0,0,0]` в эффекте, который использует этот цвет.
4. Собственные волны яркости, затухание и параметры текущего эффекта.
5. Цветовую гамма-коррекцию: при gamma 2.2 входной уровень 128 преобразуется примерно в 56.
   Некоторые эффекты учитывают гамму внутри, поэтому изменение гаммы не является универсальным решением.
6. Ограничитель тока: `leds.pwr` — расчётная оценка, а не показание измерительного прибора.
7. Белый канал W: цветные RGB-эффекты не обязаны использовать его, в отличие от белой заливки `sauluxLine`.

Выбранная в интерфейсе палитра влияет не на каждый эффект.
Например, **Pride 2015** формирует собственные цвета; низкая яркость основного цвета
сама по себе не объясняет яркость именно этого эффекта.

### Где посмотреть технические данные

- `http://<IP>/json/info` — версия, модель OTA, память, число светодиодов, оценка тока;
- `http://<IP>/json/state` — Master, сегменты, их ID, диапазоны и параметры;
- журнал интеграции WLED в Home Assistant — ошибки подключения и обработки данных.

## 16. Сборка и публикация релизов

Этот раздел нужен для самостоятельной сборки. Для обычного обновления достаточно готовых Releases.

### Локальная сборка

Нужны Git, Node.js 20+ с npm, Python и PlatformIO; зависимости Python описаны в
[requirements.txt](requirements.txt). Для native-проверок нужен также `clang++` или `g++`.

```sh
git clone https://github.com/altdaps/WLED-SAULUX.git
cd WLED-SAULUX
npm ci
npm run build
pio run
```

`pio run` собирает три окружения по умолчанию:

| Окружение | Модель |
| --- | --- |
| `saulux_2i2o` | 2I2O |
| `saulux_5i4o` | 5I4O |
| `saulux_ethernet` | ETHERNET |

Сборка только Ethernet-варианта:

```sh
pio run -e saulux_ethernet
```

Файлы создаются в `build_output/release/`.
Готовые `html_*.h` / `js_*.h` генерируются из веб-исходников; вручную их не редактируют и не коммитят.

Для воспроизведения версии конкретного релиза сначала выберите его тег,
затем подготовьте версию пакета и соберите интерфейс до прошивки:

```sh
git checkout saulux-v16.0.1-saulux.8
npm ci
python3 tools/saulux_release.py prepare saulux-v16.0.1-saulux.8
npm run build
pio run
```

Без шага `prepare` локальная сборка использует базовую версию из `package.json`,
поэтому имя файла может отличаться от опубликованного релиза.

### Проверки

```sh
npm test
python3 -m unittest discover -s test -p 'test_saulux.py'
pio run
pio run -e esp32dev
```

Проверяются аппаратные профили, миграции настроек, валидация OTA, MQTT-входы,
независимость переходов, развороты, выбор сегмента, сохранение пресетов и переполнение таймера.

### Выпуск через GitHub Actions

Для этого форка используются теги `saulux-v...`, например `saulux-v16.0.1-saulux.8`.
Тег должен соответствовать базовой версии исходников; новую версию выпускают новым тегом.

Порядок выпуска следующей версии:

1. Сохраните и отправьте изменения в свой репозиторий.
2. Создайте новый тег с новым номером, например `saulux-v16.0.1-saulux.9`, и отправьте его.
3. Дождитесь успешного workflow **SAULUX Release**.
4. Проверьте три OTA-файла, три factory-файла и `SHA256SUMS` в Releases.
5. Дождитесь успешного развёртывания Pages и проверьте `manifest.json`.

Пример команд для будущей версии `.9`, если её тег ещё не существует:

```sh
git push origin main
git tag saulux-v16.0.1-saulux.9
git push origin saulux-v16.0.1-saulux.9
```

Если запуск по тегу не произошёл, используйте **Actions → SAULUX Release → Run workflow**
и передайте существующий тег. Workflow собирает именно отмеченный тегом код.
Для Pages источником развёртывания должен быть **GitHub Actions**;
ограничения окружения `github-pages` должны разрешать теги `saulux-v*`.

Выпускать PR в исходный WLED для использования этого форка не требуется.
